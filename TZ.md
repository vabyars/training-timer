# План реализации для AI-агента · Интервальный таймер

## Задача агента

Реализуй в текущем репозитории готовое к локальному запуску SPA интервального таймера. Используй требования и сценарии приёмки ниже как условия выполнения. Макеты задают состав и основные состояния трёх экранов. Для первоначальных значений и поведения следуй требованиям документа.

## Порядок работы

1. **Подготовь проект.** Проверь состояние репозитория и прочитай применимые инструкции из `AGENTS.md`, если файл есть. Если проекта ещё нет, создай Vue 3 SPA на Vite и TypeScript в корне репозитория. Если проект уже настроен, используй его структуру и пакетный менеджер. Включи строгую проверку TypeScript и зафиксируй зависимости в lock-файле.
2. **Реализуй редактор.** Опиши типы интервалов и конфигурации тренировки. Создай начальную последовательность 10 с → 4 с. Добавь редактирование названий и длительности, переключение типа, добавление, удаление, изменение порядка и выключение звука. Проверь ограничения из раздела 2, включая блокировку запуска при ошибке.
3. **Реализуй таймер.** Вынеси расчёт состояния из компонентов Vue. Храни снимок конфигурации, выбранную длительность, дедлайн и остаток на паузе. Реализуй запуск, переходы, повторение цикла, паузу, продолжение и завершение. Проверь последовательность 10 с → 4 с, переход через границу цикла и диапазон 5–10 с.
4. **Подключи звук.** Подготовь аудио после нажатия «Начать тренировку». Вызывай звуковой сигнал при старте и смене интервала. Проверь отключение звука и продолжение визуального отсчёта при недоступности аудио.
5. **Реализуй историю.** Добавь чтение и запись версионированного JSON в `localStorage`. Регистрируй запуск один раз, сортируй записи от новой к старой и сохраняй до 50 записей. Реализуй пустое состояние, обработку ошибок и восстановление настроек через «Использовать». Проверь сценарии с перезагрузкой и повреждённым JSON.
6. **Доведи интерфейс.** Свяжи три экрана и состояния из макетов. Проверь работу при ширине 320 и 1 280 CSS-пикселей, управление с клавиатуры, видимый фокус и объявления смены интервала. Убедись, что макетные записи заменены фактической историей.
7. **Настрой проверки проекта.** Добавь базовую конфигурацию Oxlint, скрипт линтинга, pre-commit-хук и проверку типов в команде сборки. Документируй установку, запуск и подключение хука в README.
8. **Проведи приёмку.** Запусти `npm run lint` и `npm run build`. Запусти приложение локально через `npm run dev` и пройди браузерные сценарии из раздела 7. Для проверки хука вызови его в тестовой копии или временном репозитории с теми же настройками, чтобы подтвердить успешный и блокирующий сценарии без создания коммитов в рабочей ветке. Исправь обнаруженные проблемы и повтори соответствующие проверки.

## Условия завершения

В репозитории есть исходный код приложения, README, конфигурация Oxlint и pre-commit-хук. Линтинг и сборка проходят, браузерные сценарии проверены. В итоговом отчёте кратко перечисли реализованные возможности и результаты проверок. Если какую-либо проверку невозможно выполнить в доступной среде, укажи конкретную причину и что осталось проверить.

## 1. Цель и стек

Создать русскоязычное SPA для тренировок по повторяющейся последовательности интервалов. Стек — Vue 3, Vite и TypeScript в строгом режиме. Приложение работает в браузере, без сервера приложений, базы данных и регистрации. Сборка размещается на статическом хостинге.

## 2. Настройка

- На первом открытии предложить последовательность «Работа» (10 секунд) → «Отдых» (4 секунды). Цикл состоит из всех интервалов в заданном порядке.
- Пользователь может добавлять, удалять и менять порядок интервалов кнопками, а также менять их названия. Последний интервал удалить нельзя. При пустом названии выводить «Интервал N», где N — его позиция.
- Для фиксированной длительности вводится одно целое число секунд. Для случайной — минимум и максимум. Допустимые значения от 1 до 3 600 секунд включительно. Минимум может равняться максимуму.
- Для случайного режима равномерно выбирать целое число секунд из заданного диапазона при каждом входе в интервал, включая первый запуск и очередной цикл. При продолжении после паузы сохранять выбранную длительность.
- Показывать ошибки рядом с полями. Пока есть ошибки, запуск недоступен. Переключатель «Звук» включён по умолчанию.

## 3. Тренировка

- «Начать тренировку» сразу запускает первый интервал. По истечении времени начинается следующий, после последнего — снова первый. Циклы повторяются до ручной остановки. Нумерация циклов начинается с 1.
- На экране тренировки показывать название текущего интервала, номер цикла, остаток в формате ММ:СС, индикатор прогресса и название следующего интервала. Для случайного следующего интервала показывать диапазон.
- «Пауза» замораживает остаток, «Продолжить» возобновляет отсчёт с того же места, «Завершить» возвращает к настройке. Во время тренировки используется снимок конфигурации на момент запуска.
- Воспроизводить один короткий сигнал при старте и на каждой границе интервалов, включая начало нового цикла. Пауза, продолжение и остановка сигналов не вызывают. Инициализировать звук по нажатию «Начать тренировку». При недоступности звука показать сообщение и продолжить визуальный отсчёт.
- Считать остаток от дедлайна по монотонным часам браузера. При позднем обновлении продвинуть состояние до актуального интервала по исходным дедлайнам. Пропущенные сигналы не воспроизводить пачкой. В фоне и при блокировке экрана точность сигналов зависит от браузера. После перезагрузки открывать настройку.

## 4. История

- При каждом успешном запуске добавлять запись, включая тренировки, которые пользователь завершил до конца первого цикла. Запись содержит уникальный ID, дату запуска в ISO 8601 и снимок настроек с упорядоченным массивом интервалов. Хранить диапазон в исходном виде.
- Хранить до 50 последних запусков в `localStorage` под ключом `training-timer:history`. Формат JSON — объект с полями `version: 1` и `entries`. Интервал представлен названием и типом `fixed` с полем `seconds` либо типом `random` с полями `minSeconds` и `maxSeconds`. Все длительности хранятся в секундах.
- В истории показывать новые записи сверху, дату в локальном часовом поясе и последовательность интервалов. Действие «Использовать» копирует настройки в редактор. Новый запуск происходит по нажатию «Начать тренировку». Для пустой истории показать текст «Тренировок пока нет».
- Проверять версию и структуру данных при чтении. При ошибке чтения или сохранения вывести сообщение в истории и сохранить возможность тренироваться. История доступна в том же браузере и профиле.

## 5. Интерфейс

- Mobile first. От 320 CSS-пикселей элементы помещаются без горизонтальной прокрутки. Основные кнопки удобно нажимать одной рукой. Минимальная область нажатия — 44 × 44 CSS-пикселя.
- На широком экране ограничить ширину редактора и истории, чтобы поля и текст оставались читаемыми. Использовать крупный отсчёт с цифрами одинаковой ширины.
- Все действия доступны с клавиатуры. Поля имеют подписи, фокус видим. Текущая фаза обозначена текстом, смена фазы доступна экранному диктору без объявления каждой секунды.

## 6. Требования к коду

- Разнести UI, расчёт таймера, звуковые сигналы и работу с хранилищем. Описать настройки типами TypeScript. Использовать понятные имена и небольшие компоненты.
- Подключить Oxlint с базовой конфигурацией и командой `npm run lint`. Настроить версионируемый pre-commit hook, например через Husky, который вызывает эту команду и прерывает коммит при ненулевом коде выхода.
- Команда `npm run dev` запускает приложение локально. `npm run build` включает проверку типов и сборку Vite. В README описать установку, команды и подключение хука после клонирования.
